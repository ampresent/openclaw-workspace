# 爱情虫 — 游戏设计文档

创建时间: 2026-04-06

## 概念

两只虫（bugs）代表两个人。虫的皮肤有光滑和粗糙部分，光滑处碰撞产生感情线，感情线输送养分逐渐强化，最终孕育新生命。粗糙处碰撞则相互磨损。虫会变异（长瘤）、干瘪（排出体液）、记忆形变。游戏的核心问题是：爱是掏空自己来让出空间给对方。

## 关键设计决策

| 决策 | 选择 |
|------|------|
| 呈现形式 | C — 先做可交互概念原型 |
| 匹配机制 | D — 节奏先对齐，再旋律呼应/互补 |
| 玩家操作 | B — 频率筛检（瘪=只留低频，胀=全频） |
| 视觉风格 | C — 半抽象，虫身即频谱 |
| 音乐来源 | C — Web Audio 程序生成 |

## 核心循环

```
[两首程序生成旋律同时播放]
        ↓
[节奏尚未对齐] → 鼓点错位 → 产生碰撞
        ↓
[玩家操作: 瘪/胀] → 调整自己虫的频谱空间
        ↓
[AI 操作: 自动调整另一只虫] → 寻找互补/呼应
        ↓
[频率和谐区] → 光滑碰撞 → 产生感情线 → 输送养分 → 强化
[频率冲突区] → 粗糙碰撞 → 相互磨损 → 粗糙蔓延
        ↓
[感情线达到阈值] → 孕育新虫 ✅
[或] → 体液耗尽 / 过度粗糙无法连接 ❌
```

## 音乐系统

### 程序生成方案

使用 Web Audio API 实时合成两段"声部"：

- **虫 A（玩家）**：一段以低频为主的旋律（saw/triangle 波），有固定节奏型
- **虫 B（AI）**：一段以中高频为主的旋律（square/sine 波），节奏型稍有不同
- 每个"回合"是一段固定的和弦进行（4-8 小节），两段旋律在和弦框架内生成

### 匹配判定

- **节奏对齐**：两个声部的节拍重合度（通过比较 onset 时间差）
- **旋律和谐**：两个声部同时发出的音是否在当前和弦内（大三/小三/纯五等和谐音程）
- **旋律互补**：一个声部低音区时另一个在高音区，频率不重叠

### 玩家操作

- **瘪（deflate）**：玩家的虫只保留低频（<300Hz），声音变薄变闷，视觉上虫变细
- **胀（inflate）**：恢复全频，声音饱满，视觉上虫变粗
- 操作方式：鼠标点击/拖拽，或空格键切换

### AI 行为

AI 控制虫 B，行为规则明确可预测：
1. 检测当前两个声部的频率冲突区域
2. 在冲突区域自动降低自己的音量/频率
3. 在和谐区域主动增强
4. 目标是最大化"和谐面积"（两虫光滑接触面积）

## 视觉系统

### 虫的表现

每只虫是一条水平延伸的曲线，从左到右代表时间轴：
- 曲线的 Y 轴振幅 = 该时刻的音量
- 曲线的粗细 = 频率丰富度（全频=粗，只有低频=细）
- 曲线的平滑度 = 和谐度（和谐=贝塞尔曲线平滑，冲突=锯齿状）

### 皮肤质感

- **光滑段**：曲线平滑，颜色温暖（橙/粉），有光泽
- **粗糙段**：曲线锯齿状，颜色冷硬（灰/褐），无光泽
- **瘤状结节**：曲线上的突起疙瘩，颜色暗沉

### 感情线

两虫之间光滑段的连线：
- 细线 → 粗线 → 实线（强度递增）
- 线上有"养分"粒子流动（小亮点从一方流向另一方）
- 断开时有拉伸/断裂动画

### 频谱填充

虫身体内部填充当前频谱的可视化：
- 低频在底部（深色），高频在顶部（浅色）
- 瘪的时候只剩底部窄条
- 胀的时候从底到顶完整填充

## 体液经济

- 每只虫有固定的体液总量（显示为进度条/身体饱满度）
- **排出体液**：瘪的操作消耗体液（排出去让出空间）
- **回收体液**：胀的时候回收部分（不能 100% 回收，有损耗）
- 损耗去向：一部分消散，一部分用于加固与对方嵌合的部分
- 体液耗尽 → 游戏失败

## 失败/成功条件

### 成功
- 感情线强化到阈值 → 两虫之间出现"新虫"的雏形 → 胜利动画

### 失败（任一触发）
1. **体液耗尽** — 排出太多回收太少
2. **过度契合但粗糙** — 两虫嵌合太深但全是粗糙面，感情线断开后无法再建立任何新连接，逐渐萎缩死亡

## 原型范围

第一版原型只实现：
1. [ ] 两段程序生成旋律同时播放
2. [ ] 节拍可视化（脉冲/闪光标注重拍）
3. [ ] 玩家通过瘪/胀控制自己虫的频谱
4. [ ] AI 自动调整另一只虫的频谱
5. [ ] 两虫之间的碰撞检测（光滑/粗糙判定）
6. [ ] 感情线的生成、强化、断裂
7. [ ] 体液消耗与回收机制
8. [ ] 基本的成功/失败判定

不含：变异系统、记忆形变、多回合、精美美术。

## 技术方案

- **渲染**：HTML5 Canvas 2D
- **音频**：Web Audio API（OscillatorNode + BiquadFilterNode + AnalyserNode）
- **架构**：单文件 HTML（`index.html`），无构建工具
- **交互**：鼠标/键盘，无需手柄
