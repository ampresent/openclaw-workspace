# 设计决策记录

## D001: 源码组织 - Patch 栈而非 Fork
- **日期**: 2026-04-12
- **决策**: 采用 Patch 栈模式管理定制修改，Base 源码从 Rocky src.rpm 提取
- **理由**: 避免大规模 fork，便于与上游同步；Patch 可独立回滚
- **替代方案**: 完整 fork 每个包 → 维护成本过高

## D002: evo CLI 语言 - Rust
- **日期**: 2026-04-12
- **决策**: 使用 Rust 编写 evo CLI 和调度器
- **理由**: 性能、类型安全、良好的系统编程生态
- **替代方案**: Go (编译快但不够底层) / C (太原始)

## D003: 安全模型 - 用户权限隔离
- **日期**: 2026-04-12
- **决策**: Claude Code 和构建进程运行在独立低权限用户下
- **理由**: 简单有效，不需要容器化开销
- **替代方案**: 容器 (过度) / chroot (复杂)

## D004: 基础发行版 - Rocky Linux
- **日期**: 2026-04-12
- **决策**: 基于 Rocky Linux 而非 Rocklinux
- **理由**: 用户指定；src.rpm 体系成熟，spec 文件标准化
- **备注**: 原白皮书写 Rocklinux，实际指 Rocky Linux

## D005: 构建触发 - 纯手动
- **日期**: 2026-04-12
- **决策**: 构建仅由用户手动触发，不自动拉取上游
- **理由**: 防止意外构建风暴，服务器场景稳定性优先
