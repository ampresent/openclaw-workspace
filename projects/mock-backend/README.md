# Mock Backend — AI 驱动的设备/后端模拟框架

## 核心理念

传统模拟器需要手写设备寄存器行为。本项目不同：**只要给 AI 一份手册和驱动源码，它就能实时模拟该设备的响应。**

## 目标

- 构建一个可扩展的 mock 框架，通过 GDB/ptrace 拦截对设备的访问
- AI 引擎根据上下文（手册、源码、历史状态）生成合理的设备响应
- 第一个目标：模拟一张网卡（e1000/e1000e）
- 框架设计为通用，后续可模拟任意设备（磁盘控制器、GPIO、传感器等）

## 架构概览

```
┌─────────────┐     breakpoint hit     ┌──────────────┐
│  被测驱动    │ ──────────────────────→ │  拦截层      │
│  (e1000e)   │ ←────────────────────── │  (GDB/ptrace)│
└─────────────┘     注入响应            └──────┬───────┘
                                               │
                                               ▼
                                       ┌──────────────┐
                                       │  上下文引擎   │
                                       │  (RAG/索引)   │
                                       └──────┬───────┘
                                               │
                                               ▼
                                       ┌──────────────┐
                                       │  AI 响应引擎  │
                                       │  (LLM 推理)  │
                                       └──────────────┘
```

## 模块划分

### 1. Intercept Layer（拦截层）
- `gdb_backend.py` — GDB/MI 接口，设置断点、读写寄存器/内存
- `ptrace_backend.py` — ptrace 直接拦截（后续实现）
- `intercept.py` — 统一拦截抽象，注册/分发事件

### 2. Context Engine（上下文引擎）
- `context.py` — 加载手册、源码，建立可搜索索引
- 支持：PDF 手册、文本手册、C 源码、头文件

### 3. AI Response Engine（响应引擎）
- `response.py` — 调用 LLM 生成设备响应
- `state_tracker.py` — 跟踪设备状态机（寄存器、DMA、中断等）
- `protocol.py` — 设备协议知识（PCI 配置空间、MMIO、PIO）

### 4. Device Templates（设备模板）
- `devices/nic/` — 网卡模板（第一个实现）
- `devices/base.py` — 设备基类，定义通用接口

## 范围

### 包含
- GDB 拦截驱动对设备 MMIO/PIO 的读写
- AI 根据手册生成寄存器级响应
- 设备状态跟踪（有限状态机）
- 网卡基础功能：PCI 配置、寄存器读写、收发包描述符

### 不包含
- 完整的网络协议栈
- GPU 模拟
- 实时性能要求极高的场景

## 技术栈
- Python 3.10+
- GDB/MI 协议（gdb-mi 库或直接 subprocess）
- LLM API（OpenAI 兼容接口）
- 可选：ptrace (C/ctypes)

## 关键入口
- 状态文件：`STATUS.md`
- 待办列表：`TODO.md`
- 源码：`src/`
